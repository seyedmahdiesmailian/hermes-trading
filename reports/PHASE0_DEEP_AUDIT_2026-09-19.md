## ۵. اتصال لینوکس ↔ MetaTrader — بررسی گزینه‌ها

هدف شما: لینوکس مغز، ویندوز فقط MT5 + بروکر.

| گزینه | تأخیر | پیچیدگی | امنیت | وضعیت این پروژه |
|---|---|---|---|---|
| **HTTP Bridge فعلی** (Flask+waitress روی :5050، Bearer، پایتون `MetaTrader5`) | ۱–۲۰ms روی LAN | کم | متوسط (HTTP خام LAN) | **پیاده، canonical در گیت، تست AST دارد** |
| Expert Advisor MQ5 اختصاصی | tick-level | بالا (دو زبان، دو دیپلوی) | بستگی به کانال دارد | وجود ندارد؛ معادل عملیاتی‌اش همین اسکریپت پایتون است |
| WebSocket دوطرفه | sub-10ms push | متوسط | باید از نو نوشته شود | وجود ندارد؛ برای اسکالپ M5 لازم نیست |
| ZeroMQ / named pipe | کم | متوسط | خوب روی localhost | بیش از نیاز LAN |
| REST عمومی اینترنت (VPS دور) | ۵۰–۲۰۰ms | — | TLS اجباری | مناسب این توپولوژی نیست |

حکم (پیشنهاد، نه اجرا):

**همین Bridge را نگه دارید.** دلایل از روی کد:

- همهٔ endpoint های لازم هست: health, account, tick, ohlc/rates, positions, history/deals, order, partial, modify, close, pending, cancel
- auth Bearer با `hmac.compare_digest`، بدون توکن اصلاً بوت نمی‌شود
- deploy یک‌طرفه git → `C:\Temp\bridge.py` (`_deploy_bridge.py` دیگر از زنده دانلود نمی‌کند)
- کلاینت لینوکس شکل‌های قدیمی/جدید را تحمل می‌کند
- تأخیر تصمیم اسکنر ۱۵ دقیقه و مدیریت ۵ ثانیه است؛ WebSocket سودی برای expectancy ندارد

سخت‌کردن بعدی (بعد از تأیید)، نه بازنویسی:

1. bind بریج روی اینترفیس LAN نه لزوماً `0.0.0.0`، یا فایروال ویندوز فقط از `192.168.10.18`
2. TLS اختیاری است اگر شبکه فقط LAN ایزوله بماند
3. WinRM همچنان NTLM بدون اعتبار گواهی (`server_cert_validation='ignore'`) — برای دیپلوی/بکاپ، نه برای سفارش

EA اختصاصی MQ5 فقط وقتی لازم است که بخواهید منطق مدیریت را **روی ترمینال** بگذارید. این خلاف هدف «ویندوز بدون مغز» است.

## ۹. آیا معماری برای ربات حرفه‌ای مناسب است؟ (جواب دقیق)

### مناسب است برای
- یک نماد XAUUSD، یک حساب دمو، یک پوزیشن
- جداسازی مغز/دست که شما خواستید — **از قبل پیاده است**
- توسعهٔ تدریجی استراتژی، چون گلوگاه واحد و تست رگرسیون وجود دارد
- نپذیرفتن کور سیگنال تلگرام

### مناسب نیست بدون کار بیشتر برای
- ادعای «هوش مصنوعی که یاد می‌گیرد» — یادگیری فعلی سه عدد را فقط وقتی وین‌ریت <۴۰٪ و میانگین منفی باشد سفت می‌کند؛ سیستم می‌تواند با وین‌ریت ۶۵٪ و payoff 0.47 ببازد و یادگیری ساکت بماند
- فاندامنتال واقعی (تفسیر NFP/FOMC، نه فقط قفل ۳۰ دقیقه‌ای)
- چند نماد / چند حساب / پورتفولیو
- اجرای اینترنتی (بریج HTTP خام)

### مقیاس‌پذیری
عمودی برای طلا کافی است (۵ث مدیریت، ۱۵د اسکن). افقی نیست: JSON/CSV، چند پروسس روی kill_switch بدون قفل فایل، یک بریج ویندوز = SPOF.

### امنیت
برای LAN دمو قابل قبول. برای ریل روی اینترنت نه.

### بازطراحی لازم نیست
جداسازی ماشین‌ها، HTTP Bridge، گلوگاه `evaluate_proposal`، fail-closed ورود، یک پوزیشن.

### بازطراحی/تعمیر لازم است (اولویت، هنوز اجرا نشده)

1. **اقتصاد خروج** — برنده‌ها +۳۰ / بازنده‌ها −۶۳. b182 نصف در TP1 را آورده؛ روی این ژورنال هنوز payoff زیر ۱ است. این مهم‌ترین مشکل **تریدر** است نه زیرساخت
2. **b210** — گیت‌های پولی باید نت ببینند (کمیسیون روی همین ژورنال ۱۴$ است)
3. **یادگیری** — تریگر باید payoff/expectancy را ببیند نه فقط WR
4. **لایهٔ امتیاز سیگنال** — هندسهٔ غلط و TP صفر نباید verdict=execute بگیرند (مشاهده‌پذیری دروغین)
5. **verify_head روی کلون کامل** — جدا کردن fail محیطی از fail واقعی
6. **requirements.txt**

## ۱۰. تطبیق با فازبندی متن شما

| فاز متن | وضعیت واقعی بعد از بررسی عمیق |
|---|---|
| ۰ شناخت | کامل — دو گزارش |
| ۱ لینوکس = هسته | انجام شده |
| ۲ ارتباط MT5 | انجام شده (Bridge+auth). سخت‌کردن، نه ساخت از صفر |

## ۱۲. پیشنهاد فاز بعد — منتظر تأیید

با حساب **دمو** و قانون «داخل master نبر»، ترتیب پیشنهادی من این است. اجرا نمی‌کنم تا بگویید کدام را می‌خواهید:

**پیشنهاد الف (توصیه) — اقتصاد تریدر، بدون دست‌زدن به زیرساخت زنده**
- روی برنچ جلسه: حفرهٔ امتیاز سیگنال (هندسه/TP صفر → skip قطعی، نه execute دروغین)
- خواندن نت در گزارش‌ها/یادگیری (b210 کامل نیاز به re-pin ۵۰ دقیقه‌ای دارد؛ می‌توان اول مصرف‌کننده‌های غیرپین‌شده را نت کرد)
- هیچ تغییری در آستانهٔ ۶.۰، min_rr، سقف پوزیشن

**پیشنهاد ب — فقط مشاهده**
- علت‌یابی دقیق‌تر ۵۲ سیگنال (نمونه‌های raw_text) بدون تغییر گیت
- جدا کردن failهای تست محیطی از باگ واقعی

**پیشنهاد ج — زیرساخت**
- `requirements.txt`
- تلاش برای سبز کردن verify_head (ممکن است در این clone ناقص غیرممکن باشد)

تا تأیید، هیچ فازی شروع نمی‌شود.
