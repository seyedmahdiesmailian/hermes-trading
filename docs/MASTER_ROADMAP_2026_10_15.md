## فاز ۱ — انتقال و بازطراحی زیرساخت (هدف: لینوکس = هسته اصلی)

**وضعیت:** ۸۰٪ انجام شده. مهاجرت ۸ اکتبر ماشین‌ها را جدا کرد (لینوکس مغز، ویندوز فقط MT5). باقی‌مانده = **بازطراحی و پاک‌سازی**.

### ۱-۱ تصمیم سرنوشت V1 (نیاز به تایید شما)

**پیشنهاد:** آرشیو کامل V1 + استخراج منطق اثبات‌شده به سند مرجع.

**چرا نه بازیابی:**
- تاریخچه خودتان: V1 با ۶ ضرر متوالی نابود شد + مشکل cron saboteur
- وین‌ریت ۶۶٪ اما **نت −۱۵.۵۲ دلار** — یعنی واقعاً سودده نبود، فقط وین‌ریت خوب بود
- V1 مونولیتیک ۱۵٬۱۹۸ خط است؛ بازگشت به آن با هدف معماری شما در تضاد است

**مزایا (pros):**
- معماری تمیز V2 حفظ می‌شود
- منطق ارزشمند V1 (گیت‌های fail-closed، پارسرها، مدیریت ریسک) به سند قابل حمل تبدیل می‌شود
- تاریخچه git دست‌نخورده باقی می‌ماند

**معایب/ریسک‌ها (cons/risks):**
- نیاز به بازخوانی `auto_executor.py` (۷۱۴ خط) برای استخراج دقیق گیت‌ها
- **ریسک: از دست رفتن یک گیت ظریف** → mitigation: استخراج خط‌به‌خط + cross-check با ژورنال ۶۲ ترید

### ۱-۲ پاک‌سازی کد مرده + تعمیر تست‌ها
- ۴۰+ فایل V1 با import شکسته (`No module named 'engines'`)
- ۱۷ فایل تست collection error
- سرویس‌های dead: hermes-telegram-listener, hermes-signal, hermes-position
- `hermes_runtime.py` (۱٬۱۶۱ خط)، `hermes_master.py`, `position_daemon.py`, `signal_daemon.py`

### ۱-۳ یکپارچه‌سازی ذخیره‌سازی
- **الان:** `trade_journal` (۶۲ ردیف) vs `signals` (۰) vs `plans` (۱) — همگام‌سازی ندارد
- **هدف:** SQLite (`hermes.db`) = single source of truth؛ JSON فقط برای handoff بین پروسه‌ها
- **روش:** migration تدریجی با dual-write، بدون big-bang (سیستم زنده است)

### ۱-۴ رفع سکوت position daemon
- ۷ روز بدون خروجی — خواندن JSON خالی → loop بدون لاگ
- نیاز: heartbeat + لاگ ساختاریافته + alert روی silence

### ۱-۵ یکپارچه‌سازی کانفیگ
- کرون واقعی ۵ دقیقه، مستندات ۱۵ دقیقه (سه منبع، دو عدد)
